01 · Problem

Problem

Production DevOps assistants must retain context across past investigations within a tenant boundary, warn engineers before risky config changes ship, verify every metric in generated postmortems, and gate prompt updates against judge bias.

Agentic DevOps & Eval

Overview

DevOpsChatEval partitions 14 AWS microservice outages across 3 isolated customer Spaces in SQLite WAL (0 cross-tenant leaks), retrieving correlated incidents in 3.518 ms median via BM25 plus 2-hop service topology traversal. Before code merges, a static diff analyzer checks timeouts, connection pools, retry loops, SQS visibility windows, and IAM wildcards in 3.406 ms median (6 / 6 risky diffs blocked, 0 / 4 false positives). For incident reporting, a 3-stage AWS Correction-of-Error (COE) pipeline drafts 5 structured sections on Amazon Nova Lite and strips unverified metrics, UTC timestamps, or service names in 1.175 ms median (12 / 12 injected hallucinations caught). Finally, a position-swapped LLM-as-a-Judge runs both Judge(A, B) and Judge(B, A) on Amazon Nova Micro across 16 golden cases, reaching Cohen's κ = 0.8072 against human SRE labels and promoting prompt v3 at a 93.8% debiased win rate.

01 · LOST INVESTIGATION CONTEXT

One-Shot Triage Forgets Shared Dependencies

When an engineer asks follow-up questions across outages, stateless bots miss shared upstream or downstream bottlenecks such as two microservices saturating the same Aurora cluster weeks apart.

02 · REPEAT CONFIG OUTAGES

Risky Diffs Ship Without Historical Checks

Lowering an HTTP timeout below a downstream service's p99 latency or raising ECS pool sizes above RDS max_connections triggers avoidable repeat SEV-1 incidents if not caught pre-deploy.

03 · UNVERIFIED POSTMORTEMS

Drafted Incident Reports Invent Telemetry

Freeform LLM postmortems can fabricate packet-loss percentages, off-by-hours UTC timestamps, or nonexistent service names that erode trust during executive Correction-of-Error reviews.

04 · JUDGE POSITION BIAS

Single-Order LLM Judges Favor Slot Position

Promoting a tuned system prompt using a single pairwise judge pass conflates real grounding gains with first-position or verbosity bias unless swapped pairs and human calibration are enforced.

03 · Implementation

Implementation

Four modular Python 3.12 subsystems handle multi-tenant Space memory and retrieval, pre-deployment diff risk scoring, verified Correction-of-Error content generation, and position-swapped prompt evaluation.

12 / 12 Unit Tests Passing
01 · MULTI-TURN CHAT & INCIDENT MEMORY GRAPH devops_chat_eval/chat_memory.py
Each customer environment (space-prod-payments, space-prod-fulfillment, space-prod-identity) owns an isolated incident graph and multi-turn conversation history so follow-up questions correlate shared dependencies without leaking foreign tenant telemetry.
DevOpsChatMemoryStore runs SQLite with PRAGMA journal_mode=WAL, combines BM25 scoring (k1=1.5, b=0.75) with 2-hop traversal across service_edges in 3.518 ms median (7.098 ms p95), carries session entities across turns, calls us.amazon.nova-lite-v1:0, and verifies every bracketed [INC-2xx] citation against the active Space (8 / 8 recall, 0 cross-tenant leaks).
02 · PRE-DEPLOYMENT DIFF RISK ANALYZER devops_chat_eval/deploy_risk.py
Before a pull request or infrastructure template ships, engineers test unified diffs, YAML/JSON configs, or Python changes against Space capacity thresholds and historical incident signatures to stop repeat outages.
analyze_deploy_diff() evaluates 7 static rules (DR-TIMEOUT-01 through DR-HOTPATH-07) in 3.406 ms median, checking client timeouts against downstream p99 latencies, pool_size * task_count against Space RDS max_connections, retry jitter, circuit breakers, SQS VisibilityTimeout vs worker Timeout, and IAM * wildcards, blocking 6 / 6 hazardous diffs with 0 / 4 false positives.
03 · FACT-VERIFIED AWS COE CONTENT WORKFLOW devops_chat_eval/coe_workflow.py
Turning raw incident timelines and CloudWatch alarms into an AWS Correction-of-Error (COE) postmortem requires every metric, UTC timestamp, and service name in the document to match underlying telemetry.
generate_verified_coe() extracts canonical allowed numbers, UTC timestamps, alarms, and service identifiers from SQLite, prompts us.amazon.nova-lite-v1:0 for a 5-section JSON draft (Executive Summary, Impact Metrics, Incident Timeline, 5-Whys, Action Items), and passes every clause through verify_and_scrub_coe_draft() in 1.175 ms median (catching 12 / 12 injected hallucinations).
04 · PROMPT TUNING & SWAPPED LLM-AS-A-JUDGE devops_chat_eval/judge_arena.py · server.py
Engineers and Applied Scientists compare candidate prompt templates (v1, v2, v3, or custom edits) across 16 golden DevOps cases and promote a prompt only when debiased quality, telemetry recall, and latency pass threshold gates.
evaluate_position_swapped_pair() executes both forward Judge(A, B) and swapped Judge(B, A) passes on us.amazon.nova-micro-v1:0 alongside verified rubric signals, neutralizing slot flips into POSITION_BIAS_CAUGHT ties, computing multi-class Cohen's κ = 0.8072 against human SRE labels, and gating PROMOTE / HOLD decisions via lambda_handler().
04 · Trade-Offs

Trade-Offs

Every architectural choice balances Bedrock inference cost and latency against factual grounding guarantees, position-bias resistance, and zero-idle serverless operation.

Design Decisions
01 · 2X JUDGE CALLS VS POSITION BIAS

Doubling Pairwise Judge Passes Eliminates Slot Favoritism

Running both Judge(A, B) and Judge(B, A) doubles judge invocations per case (942.0 ms median pair latency on us.amazon.nova-micro-v1:0), but costs only $0.00824 across the entire 151-call benchmark suite while catching 3 genuine position-bias flips on close and symmetric pairs that would otherwise corrupt win rates.

02 · CLAUSE SCRUBBING VS RETRY LOOPS

Deterministic Clause Stripping Over Unbounded LLM Re-Prompting

Re-prompting an LLM when a postmortem draft contains an unverified number adds 1.5s to 3.5s of tail latency and still cannot guarantee zero drift. Deterministic clause-level scrubbing in coe_workflow.py removes unverified metrics, UTC timestamps, and service names in 1.175 ms median while preserving verified sections.

03 · BM25 + TOPOLOGY GRAPH VS EMBEDDINGS

Exact Identifier Matching Plus Explicit Dependency Edges

Dense vector embeddings often blur exact alarm names, deploy SHAs, and INC-2xx identifiers while requiring an external vector cluster. Combining BM25 lexical scoring with 2-hop SQLite service_edges traversal hits 100.0% top-3 recall in 3.518 ms median at $0.00/hr idle cost, trading away fuzzy paraphrase matching on non-technical prose.

04 · NOVA LITE + MICRO MODEL SPLIT

Tiered Bedrock Routing for Interactive Depth vs Batch Eval Speed

Using us.amazon.nova-lite-v1:0 (1,378.0 ms median) for multi-turn DevOps chat and 5-section COE authoring delivers richer causal explanations, while routing high-volume candidate generations and swapped pairwise judging to us.amazon.nova-micro-v1:0 (665.0 ms median) keeps interactive A/B prompt tuning fast and economical.
